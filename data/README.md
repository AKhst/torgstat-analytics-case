# Synthetic SaaS Dataset

The core CSV files are generated by `scripts/generate_data.py`. Historical FX rates are produced separately by `scripts/fetch_fx_rates.py`. The importer validates exact column order and loads every file into the PostgreSQL `raw` schema with source metadata.

Generation is deterministic with seed `42`. The source data follows the approved v1 contracts while retaining a small number of documented quality defects for analytics-engineering exercises.

## Dataset Summary

| File | Deterministic rows | Grain |
| --- | ---: | --- |
| `workspaces.csv` | 200 | One current workspace |
| `plans.csv` | 4 | One product plan |
| `users.csv` | 2,500 | One current user |
| `sessions.csv` | 1,297 | One user session |
| `subscriptions.csv` | 180 | One stable subscription lifecycle |
| `subscription_plan_history.csv` | 234 | One plan period per subscription |
| `invoices.csv` | 935 | One invoice per subscription billing period |
| `events.csv` | 5,000 | One workspace product event occurrence |
| `fx_rates.csv` | Refreshed separately | One currency rate for a date and pair |

## Relationships

```text
workspaces 1 ─── * users 1 ─── * sessions
     │
     ├── * subscriptions 1 ─── * subscription_plan_history * ─── 1 plans
     │            └── * invoices ──────────────────────────────── 1 plans
     └── * events
```

Every workspace has an owner record. Every active workspace has exactly one active owner. A workspace may have no subscription, and a subscription may change plan without changing `subscription_id`.

## File Schemas

### `workspaces.csv`

`workspace_id`, `workspace_name`, `created_at`, `country_code`, `customer_segment`, `billing_currency`, `is_active`.

### `plans.csv`

`plan_id`, `plan_name`, `tier_rank`, `monthly_price`, `annual_price`, `is_active`.

### `users.csv`

`user_id`, `workspace_id`, `created_at`, `country_code`, `user_role`, `signup_type`, `has_gdpr_consent`, `is_active`, `deleted_at`.

### `sessions.csv`

`session_id`, `user_id`, `started_at`, `utm_source`, `utm_medium`, `is_first_session`.

### `subscriptions.csv`

`subscription_id`, `workspace_id`, `started_at`, `ended_at`, `status`.

### `subscription_plan_history.csv`

`subscription_plan_period_id`, `subscription_id`, `plan_id`, `billing_frequency`, `valid_from`, `valid_to`, `change_type`.

`valid_to` is inclusive. Consecutive plan periods therefore use `previous.valid_to = next.valid_from - 1 day`.

### `invoices.csv`

`invoice_id`, `subscription_id`, `workspace_id`, `plan_id`, `billing_frequency`, `issued_at`, `due_at`, `period_start`, `period_end`, `currency`, `net_amount`, `tax_amount`, `gross_amount`, `payment_status`, `paid_at`.

Monthly subscriptions produce monthly invoices, annual subscriptions produce annual prepaid invoices, and Free plan periods do not produce financial invoices.

### `events.csv`

`workspace_id`, `event_date`, `event_name`, `properties`.

### `fx_rates.csv`

`rate_date`, `base_currency`, `quote_currency`, `rate`.

## Data-Quality Scenarios

The deterministic v1 files contain controlled defects rather than accidental identifier collisions:

- 1% of users have an invalid raw `created_at` value;
- approximately 2% of users have no `country_code`;
- approximately 1% of first sessions lose `utm_source` in addition to valid missing attribution for invited users;
- approximately 2% of invoices have no source currency;
- approximately 1% of invoices violate `net_amount + tax_amount = gross_amount`;
- approximately 3% of eligible historical invoices have `payment_status = failed`.

Global identifiers remain unique, plan-history periods do not overlap, sessions are never generated before the user's valid creation timestamp, and each user with sessions has exactly one earliest first session.

## Regenerate and Load

```bash
python scripts/generate_data.py
python scripts/fetch_fx_rates.py
python scripts/import_to_postgres.py
```

The FX refresh requires network access. The current importer replaces raw tables and therefore requires dependent dbt models to be rebuilt after every load.
