# Synthetic SaaS Dataset

The core files in this directory are generated by `scripts/generate_data.py`. The separate `fx_rates.csv` reference file is produced by `scripts/fetch_fx_rates.py`. All files simulate source extracts and are loaded without transformation into the PostgreSQL `raw` schema by `scripts/import_to_postgres.py`.

The generator fixes both Python's and NumPy's random seeds to `42`, so repeated runs produce the same dataset with the current code.

## Dataset Summary

| File | Rows | Description |
| --- | ---: | --- |
| `plans.csv` | 4 | Subscription plan reference data |
| `users.csv` | 2,500 | Users assigned to workspaces |
| `sessions.csv` | 1,000 | User acquisition sessions |
| `subscriptions.csv` | 200 | One generated subscription per workspace |
| `invoices.csv` | 2,280 | Up to 12 billing periods per subscription |
| `events.csv` | 5,000 | Workspace-level product events |
| `fx_rates.csv` | 1,734 | Historical USD, EUR, and GBP exchange rates |

Row counts reflect the current deterministic generator. Invoice periods are skipped with a 5% probability, which produces 2,280 invoices with seed `42`.

## Relationships

```text
plans.plan_id ──────────────┬──< subscriptions.plan_id
                            └──< invoices.plan_id

users.user_id ─────────────────< sessions.user_id

users.workspace_id ──> workspaces <── subscriptions.workspace_id
                                      invoices.workspace_id
                                      events.workspace_id

subscriptions.subscription_id ──────< invoices.subscription_id
```

There is no separate `workspaces.csv`; workspace IDs are generated as shared business keys. A subscription belongs to a workspace, not directly to an individual user.

## File Schemas

### `plans.csv`

| Column | Generated type | Description |
| --- | --- | --- |
| `plan_id` | integer | Plan identifier |
| `plan_name` | string | `Free`, `Starter`, `Pro`, or `Enterprise` |
| `billing_period` | string | `monthly` or `annual` |
| `price` | integer | Base price used to calculate invoices |

### `users.csv`

| Column | Generated type | Description |
| --- | --- | --- |
| `user_id` | integer | User identifier |
| `workspace_id` | string | Workspace business key |
| `signup_date` | date-like string | Valid dates plus intentionally invalid values |
| `country` | nullable string | Country code, `EU_UNKNOWN`, or null |
| `gdpr_consent` | boolean | Generated consent flag |
| `is_deleted` | boolean | Soft-deletion flag; approximately 5% are true |

### `sessions.csv`

| Column | Generated type | Description |
| --- | --- | --- |
| `session_id` | string | Session identifier |
| `user_id` | integer | References `users.user_id` |
| `session_date` | date | Session date |
| `utm_source` | string | `capterra`, `g2`, or `linkedin_ads` |
| `utm_medium` | string | Always `cpc` in the current generator |
| `is_first_session` | boolean | First-session flag; approximately 20% are true |

### `subscriptions.csv`

| Column | Generated type | Description |
| --- | --- | --- |
| `subscription_id` | integer | Random subscription identifier |
| `workspace_id` | string | References the shared workspace key |
| `plan_id` | integer | References `plans.plan_id` |
| `start_date` | date | Subscription start date |
| `status` | string | `active`, `churned`, or `MISSING_STATUS` |

### `invoices.csv`

| Column | Generated type | Description |
| --- | --- | --- |
| `invoice_id` | integer | Random invoice identifier |
| `subscription_id` | integer | References `subscriptions.subscription_id` |
| `workspace_id` | string | References the shared workspace key |
| `plan_id` | integer | References `plans.plan_id` |
| `period_start` | date | Billing period start |
| `period_end` | date | Billing period end |
| `currency` | nullable string | `EUR`, `GBP`, `USD`, or null |
| `net_amount` | numeric | Plan price before tax |
| `tax_amount` | numeric | 20% of the plan price |
| `gross_amount` | numeric | Net plus tax, with injected negative values |
| `paid` | boolean | Payment flag; approximately 5% are false |

### `events.csv`

| Column | Generated type | Description |
| --- | --- | --- |
| `workspace_id` | string | References the shared workspace key |
| `event_date` | date | Product event date |
| `event_name` | string | `dashboard_viewed`, `export_limit_reached`, or `login` |
| `properties` | JSON string | Currently contains a fixed browser property |

### `fx_rates.csv`

| Column | Generated type | Description |
| --- | --- | --- |
| `rate_date` | date | Date on which the rate applies |
| `base_currency` | string | Invoice currency, such as `EUR`, `GBP`, or `USD` |
| `quote_currency` | string | Reporting currency; currently `USD` |
| `rate` | numeric | Units of USD for one unit of the base currency |

The FX file contains rates for invoice-period dates and is used by `fct_invoices_converted`. Missing invoice currencies are normalized to `UNKNOWN` and remain unconverted.

## Injected Data-Quality Issues

The current generator intentionally introduces:

- the invalid signup date `2023/13/45` for approximately 10% of users;
- null and nonstandard country values;
- null invoice currencies;
- negative invoice gross amounts;
- missing subscription status represented by the string `MISSING_STATUS`;
- unpaid invoices and skipped billing periods;
- random numeric identifiers that are not explicitly checked for uniqueness.

With the current deterministic seed, the generated files contain one repeated subscription identifier and 23 repeated invoice identifier rows. The dbt staging models preserve these records and expose duplicate counts and boolean quality flags.

The current generator does not create mixed valid date formats, discounts, payment retries, plan upgrades/downgrades, or intentional duplicate rows. Older documentation described those features, but they are not present in `generate_data.py`.

## Regenerate and Load

From the repository root:

```bash
python scripts/generate_data.py
python scripts/fetch_fx_rates.py
python scripts/import_to_postgres.py
```

The importer loads every existing CSV, including `fx_rates.csv`, into a table with the same base name in the configured `RAW_SCHEMA`. It drops each old table with `CASCADE` before recreating it, so dependent dbt relations must be rebuilt afterward.
